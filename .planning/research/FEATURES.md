# Feature Research

**Domain:** Journal/publication archive site + conference audio/video archive (nonprofit theological fellowship, static site, zero-maintenance)
**Researched:** 2026-08-10
**Confidence:** MEDIUM (WebSearch-verified across sermon archives, academic journal sites, magazine back-issue platforms, and Pagefind official docs; no single directly-comparable "small confessional journal on a static site" example was found, so specifics are synthesized/extrapolated — flagged per-item below)

## Feature Landscape

### Table Stakes (Users Expect These)

Features users assume exist on any credible archive/journal site. Missing these makes the site feel broken or unfinished, or actively harms discoverability of the 413+ articles.

| Feature | Why Expected | Complexity | Notes |
|---------|--------------|------------|-------|
| Issue table-of-contents pages | Every academic/magazine archive organizes by issue first (WTJ archive, JMEMS archive); users arriving from a citation or old bookmark expect to land on "Issue 77" and see its full article list | LOW | Already an Active requirement. Generated at build time from metadata, one page per issue. |
| Author index + author pages (all articles by X) | Confirmed pattern across academic journal sites (author/citation indexing) and sermon archives (browse by speaker); BRF nav already promises "Authors" browsing | LOW–MEDIUM | Depends on consistent author metadata extraction from OCR (flagged as unresolved dependency in PROJECT.md). Once metadata exists, generating the page is a simple build-time aggregation. |
| Topic/category browsing | Sermon archives (SermonAudio topics/scripture) and the current BRF site itself both treat topic browsing as core navigation, not a bonus | LOW–MEDIUM | Same metadata dependency as author pages. Existing Squarespace category taxonomy should be preserved/mapped, not reinvented. |
| Inline full-text article view (HTML, not just PDF) | Already an Active requirement; also table stakes because forcing every reader to open a PDF for a single quote or citation is a known friction point on older archive sites | MEDIUM | Depends on OCR output being clean enough to convert to structured Markdown/MDX per article (unresolved dependency). |
| Downloadable PDF per article | Already an Active requirement; readers of theological content routinely want to save/print/share the "real" typeset version | LOW | Static file, no server logic needed. |
| Full-text search across all articles | Already an Active decision (Pagefind); confirmed as standard on academic and sermon archives (WTJ keyword search, SermonAudio "search within contents") | MEDIUM | Pagefind is static/client-side, confirmed to support large sites via chunked index loading — no server search backend needed. Verify with a 413-article, PDF-heavy corpus during build testing. |
| Breadcrumb navigation | Standard on any site with 3+ levels of hierarchy (Home > Journal > Issue 77 > Article); without it, users landing deep via search have no sense of place | LOW | Purely a template/UX concern, no data dependency beyond the issue/article hierarchy already required. |
| Mobile-responsive design | Baseline expectation for any 2026 site, doubly so for a long-form reading audience that includes pastors/students reading on phones | LOW–MEDIUM | Covered by the "fresh, modern, beautiful, fast" design constraint already in PROJECT.md. |
| Conference archive listing (chronological, by conference) | Confirmed pattern from LDS General Conference archive and general "back issue" conventions: browse by date, one page per event with all sessions/media | LOW | Already an Active requirement (18+ conference pages). |
| Print-friendly article view (CSS print stylesheet) | Confirmed as a stated feature on multiple magazine/digital-edition platforms ("print articles anytime"); especially relevant for long theological essays readers want to print for study/annotation | LOW | Pure CSS (`@media print`), no JS or backend. Cheap to add, notably absent from many small ministry sites — worth doing since it's nearly free. |
| XML sitemap + clean semantic HTML | Not explicitly requested by users but functions as table stakes infrastructure — without it, Google will not properly index 400+ archive pages, which defeats the purpose of migrating a discoverable public archive | LOW | Auto-generated by nearly every static site generator (Astro, Eleventy, Next static export, etc.) at build time. |
| 301 redirect map from old URLs | Already an Active requirement; without it the site "breaks" for every inbound link, bookmark, and citation pointing at the old Squarespace URLs | MEDIUM | Already flagged in PROJECT.md as deferred to implementation-time research. |

### Differentiators (Competitive Advantage)

Features that go beyond baseline and align with the Core Value ("every piece of existing content, fully reachable, zero ongoing maintenance"). None of these are expected by users walking in, but each adds real value for a 413-article, 18-conference archive without adding server/maintenance burden.

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| "Cite this article" snippet (Chicago/Turabian-style reference string) | BRJ is used by pastors, students, and researchers who want a clean citation for sermons/papers; academic and quasi-academic journal sites treat this as standard, but almost no small ministry archive site offers it — genuine differentiator at near-zero cost | LOW | Pure string templating from existing metadata (author, title, issue, date, page range if known) rendered at build time. No JS, no backend. |
| Related-articles / "more by this author" / "more from this issue" | Confirmed valuable pattern (magazine platforms note "related content" and "collections" as retention features); with 413 articles across a handful of core authors, this meaningfully increases the chance a reader discovers relevant material instead of leaving after one article | LOW–MEDIUM | Computed at build time from shared topic tags / same author / same issue — no runtime lookup, no recommendation engine. Depends on topic/author metadata already required for browsing. |
| RSS/Atom feed for new content | Confirmed as a common (though inconsistent) feature on digital-edition and journal platforms; low-effort way to let a small but committed readership (pastors, elders, subscribers) know when a new conference, news alert, or translation is posted, without requiring a mailing list or backend | LOW | Most static site generators (Astro, Eleventy, Hugo) generate RSS/Atom as a build-time output from front-matter dates — no server, no email infrastructure. Scope to "new content" feed, not full per-article feed noise. |
| Faceted search (filter by issue/author/topic combined with keyword query) | Pagefind natively supports tagging pages with `data-pagefind-filter` and returns filter counts at build time — this is a genuine capability gap vs. many small archive sites that only offer flat keyword search | MEDIUM | Verified via Pagefind official docs. Requires each article page to carry filter attributes for author/issue/topic (data already needed for browsing pages, so mostly a templating task, not new data collection). |
| Reading-optimized typography (measured line length, generous leading, serif or reading-tuned font for long-form theological prose) | Distinguishes the new site from the Squarespace original and from generic archive sites; supports the stated "beautiful, fast" design goal specifically for an audience doing sustained reading of 3,000+ word essays | LOW | Design/CSS decision, not a technical feature — call out explicitly during design phase so it isn't lost among functional requirements. |
| Social share preview images (OG images) per article/conference | When BRF content is shared on social media or in forums (a real behavior in Reformed circles — articles get linked in discussions), a proper preview card meaningfully increases click-through vs. a bare link | LOW–MEDIUM | Static OG image generation at build time (per global CLAUDE.md convention: `next/og` or equivalent static-image generation library depending on chosen SSG) — no runtime image service needed. |
| Conference speaker index | Mirrors the author-index pattern for the journal side; confirmed valuable pattern from LDS General Conference archive (speaker-ordered session listing) | LOW–MEDIUM | Depends on speaker names being captured as structured metadata per conference/session — should piggyback on whatever metadata scheme is built for conference migration. |
| Search result snippets with matched-term highlighting | Confirmed as a default Pagefind UI capability, essentially "free" once Pagefind is wired up | LOW | No extra work beyond adopting Pagefind's default UI component instead of building custom search results rendering. |

### Anti-Features (Commonly Requested, Often Problematic)

Features that look good on a checklist for "archive site" or "publication platform" but directly conflict with the zero-maintenance, static-only, no-database constraints already established in PROJECT.md.

| Feature | Why Requested | Why Problematic | Alternative |
|---------|---------------|------------------|-------------|
| User accounts / login / saved bookmarks | Many magazine/digital-edition platforms offer "save articles to your library"; feels like a natural fit for a large archive | Requires auth, session storage, a database — directly violates "no database, no headless CMS" and "zero server maintenance" constraints | Rely on browser-native bookmarking; ensure clean, stable, permanent URLs per article so browser bookmarks and search-engine caches work reliably instead |
| Comments / reader discussion threads | Common on magazine and blog platforms; feels like it increases engagement | Ongoing moderation burden (doctrinally sensitive content is a spam/troll magnet), requires either a third-party service (Disqus-style, privacy/ad concerns) or custom backend — conflicts with zero-maintenance goal | None on-site. If BRF wants discussion, point to existing external channels (their own social presence) rather than hosting it |
| AI "ask questions about the archive" chatbot | Trendy pattern SermonAudio recently added ("Ask!" — LLM-grounded Q&A over sermon library); superficially a great fit for 413 theological articles | Ongoing API/hosting cost undermines "zero ongoing maintenance"; more importantly, doctrinal-accuracy risk — an LLM paraphrasing/synthesizing confessional theology can misstate positions in ways a fellowship built around a specific doctrinal basis cannot tolerate | Strong full-text search (Pagefind) plus good topic/author browsing gets readers to the *actual* text quickly without a paraphrase-accuracy risk |
| Paywall / subscription gating for archive content | Some digital magazine platforms gate back issues behind subscriptions; "protecting" premium content is a common instinct | Contradicts BRF's existing model — the live site has no paywall, and the whole point of migration is a fully public, freely reachable archive; adding gating here would also require accounts/payments (see above) | None — keep 100% of migrated content freely accessible, matching current site behavior |
| In-browser advanced PDF viewer with annotation/highlighting | Digital magazine platforms (3D Issue, PocketMags-style) build rich embedded viewers with bookmarks/notes | High complexity (JS PDF rendering library, state management for annotations, likely needs storage/accounts to persist notes) for a feature that duplicates what the browser's native PDF viewer or a simple download link already does | Serve the PDF as a plain static download link; readers who want more use their own OS/browser PDF tools |
| Native mobile app | "App" feels like a natural companion for an archive with audio/video (mirrors SermonAudio's app, Readly's app) | Massive maintenance overhead (App Store review cycles, OS updates, separate codebase) for a niche 413-article/18-conference audience — the opposite of zero-maintenance | Responsive, fast-loading static web site; optionally a lightweight PWA manifest for "add to home screen" if offline/app-like feel is wanted later (low-cost, no app store) |
| Server-rendered/hosted search backend (Algolia, Elasticsearch, custom API) | The "obvious" way to do full-text search on a large corpus, especially since 413 articles + growing conference content feels like it needs a real search service | Requires a running server or paid SaaS dependency and API keys to manage — conflicts directly with the "static site, no runtime server" architecture decision already made | Pagefind (already decided) — confirmed via official docs to handle large corpora client-side via chunked index loading, with no hosted infrastructure |
| Personalized/ML-based content recommendations | "Because you read X, you might like Y" feels modern and increases engagement on commercial platforms | Requires user tracking, a recommendation model, and either client-side ML or a backend — wildly disproportionate for a 413-article static archive with no accounts | Build-time "related articles" by shared topic tag / same author / same issue (see Differentiators) — same reader value, zero runtime infrastructure |
| Machine translation of articles on demand | The site already has a Translations section; on-the-fly auto-translate (Google Translate widget or similar) seems like an easy way to extend reach | Doctrinal precision matters for this content — machine translation of confessional theology risks misrepresenting positions, and a live translation widget is a third-party script dependency with its own reliability/privacy tradeoffs | Keep the existing pre-translated Translations section as-is (human-translated, already vetted); do not add automatic translation |

## Feature Dependencies

```
Full-text search (Pagefind)
    └──requires──> Article text extracted as structured HTML/MDX
                       └──requires──> OCR pipeline output from Vellum-VPS (UNRESOLVED — flagged in PROJECT.md)

Author index / author pages
    └──requires──> Per-article author metadata (consistent naming)
                       └──requires──> OCR/metadata extraction resolving author attribution (UNRESOLVED)

Topic browsing
    └──requires──> Per-article topic/category metadata
                       └──requires──> Existing Squarespace category taxonomy preserved or re-mapped

Related-articles suggestions ──enhances──> Author pages, Topic browsing, Issue TOC pages
    └──requires──> Author metadata AND Topic metadata (built on top, not a new dependency)

Faceted search (Pagefind filters) ──enhances──> Full-text search
    └──requires──> Author metadata AND Topic metadata AND Issue metadata tagged as Pagefind filter attributes

Cite-this-article snippet
    └──requires──> Author + title + issue + date metadata (same metadata as author/topic pages — no new data collection)

Conference speaker index
    └──requires──> Per-conference/session speaker metadata (parallel dependency to journal author metadata, separate data source)

RSS/Atom feed
    └──requires──> Publish-date metadata per content item (issues, conferences, news alerts)

Breadcrumb navigation
    └──requires──> Issue > Article hierarchy (already required by issue TOC pages — no new dependency)

301 redirect map ──conflicts with nothing, but blocks──> Safe DNS cutover
    └──requires──> Full inventory of live Squarespace URLs (UNRESOLVED — deferred to implementation-time research per PROJECT.md)
```

### Dependency Notes

- **Search, author pages, topic browsing, and citations all trace back to the same unresolved OCR/metadata dependency.** This is the single highest-leverage blocker in the whole feature set — until OCR output format and article-boundary extraction are solved (flagged in PROJECT.md as a content-ingestion phase dependency), none of the table-stakes browsing/search features can be built for real content. Roadmap should sequence a metadata-schema decision very early, even if actual OCR text arrives later.
- **Faceted search and related-articles are pure enhancements layered on top of metadata that table-stakes features already require** — they add no new data-collection burden, only templating/UI work, once author/topic/issue metadata exists per article.
- **Conference speaker metadata is a separate, parallel effort from journal author metadata** — different source data (conference program info vs. OCR'd journal articles), so it should not be assumed to piggyback on the journal metadata pipeline.
- **The redirect map is independent of all content features** but is a hard gate on cutover — it can be researched/built in parallel with content migration, not sequentially after it.

## MVP Definition

### Launch With (v1)

Minimum viable product — matches the Active requirements already in PROJECT.md plus the near-zero-cost table-stakes items identified in this research.

- [ ] Issue table-of-contents pages (all 77 issues) — core navigational structure, everything else hangs off this
- [ ] Author index + author pages — explicitly promised by existing nav ("Issues, Authors & Topics")
- [ ] Topic/category browsing — same nav promise
- [ ] Inline full-text article view + downloadable PDF for all 413+ articles — the core value proposition of the migration
- [ ] Full-text search (Pagefind) — already decided, essential for a 413-article corpus to be usable at all
- [ ] Breadcrumb navigation — near-zero cost, prevents "lost in the archive" feeling
- [ ] Print-friendly CSS for articles — near-zero cost, high value for long-form theological reading
- [ ] XML sitemap — near-zero cost, essential for the archive to actually be found/indexed
- [ ] Conference archive (18+ conferences, video + audio) — Active requirement
- [ ] 301 redirect map — Active requirement, hard gate on cutover
- [ ] Literature/books section, Translations, BRF News Alert, About/Doctrinal/Membership/Contact pages — Active requirements, lower complexity than journal/conference work

### Add After Validation (v1.x)

Add once the core archive is live, indexed by search engines, and confirmed working end-to-end.

- [ ] "Cite this article" snippet — trigger: once metadata pipeline is stable, this is a cheap addition with no new data needed
- [ ] Related-articles by topic/author/issue — trigger: once topic/author metadata has been validated as accurate across the full corpus (bad related-article suggestions from noisy OCR metadata would be worse than none)
- [ ] RSS/Atom feed for new content — trigger: once the site has a cadence of new content being added (next conference, next news alert) worth subscribing to
- [ ] Faceted search (Pagefind filters) — trigger: once basic keyword search is confirmed working well; filters are a UX refinement, not a launch blocker
- [ ] OG social share images — trigger: once core pages are stable (image templates need final page structure to reference)
- [ ] Conference speaker index — trigger: once conference metadata (speaker names) has been captured during conference migration

### Future Consideration (v2+)

Defer until the core migration has been live and stable for a while.

- [ ] PWA manifest ("add to home screen") — why defer: nice-to-have polish, not requested, no evidence of user demand for offline/app-like access
- [ ] Privacy-friendly static analytics surfacing "most-read articles" (e.g. Cloudflare Web Analytics, already available on the existing Cloudflare account) — why defer: useful for future content decisions but not needed for launch; adding it later requires no migration/backfill since it's forward-looking only

## Competitor Feature Analysis

| Feature | Academic journal sites (WTJ archive, JMEMS) | Sermon archives (SermonAudio) | Our Approach |
|---------|----------------------------------------------|--------------------------------|--------------|
| Issue/date-based browsing | Yes — core organizing structure | Partial — organized by date/series rather than "issue" | Issue TOC pages as primary structure (matches BRF's existing nav) |
| Author/speaker browsing | Yes — author indices, citation databases | Yes — browse by speaker | Author index + author pages, generated at build time from OCR metadata |
| Topic browsing | Partial — keyword/subject indexing, less central | Yes — dedicated topic pages, core nav item | Topic browsing as a first-class nav item (matches existing site) |
| Full-text search | Yes, often gated behind subscription/EBSCO | Yes — full content search across millions of sermons | Free, ungated, client-side full-text search (Pagefind) — no paywall, no server |
| PDF download | Yes, standard for academic archives | N/A (audio/video medium) | PDF download per article, alongside inline HTML text |
| Citation formatting | Yes — DOIs, citation export, indexing services | No | Lightweight "cite this article" text snippet — no DOI infrastructure needed for a non-indexed confessional journal |
| AI/chatbot Q&A | No | Yes — SermonAudio's new "Ask!" feature | Deliberately excluded (anti-feature) — doctrinal-accuracy risk outweighs novelty |
| Accounts/paywall | Yes, common (subscription access) | No (free) | No accounts, no paywall — matches SermonAudio's free model, not the academic-paywall model |
| Conference/session speaker listing | N/A | N/A (sermon-specific, but LDS General Conference archive is the closest analog: per-session speaker ordering) | Conference speaker index as a v1.x differentiator |
